Hardware settings

Reference information for an ESP32/Arduino gateway.

U
⌁
LOCAL BUZZER IS PRIMARY

Obstruction confirmation should activate the buzzer directly on the microcontroller. Do not make the alarm depend on browser audio, a server, or internet access.

Device event endpoint reference

The following endpoint is documentation only. This HTML/CSS-only site does not send or receive requests.

http://localhost:3000/api/hardware/events

Example gate status payload:

{"type":"gate","id":"gate6","status":"obstructed","note":"Obstruction confirmed","temperature":27.4}

Example temperature-only payload:

{"type":"sensor","id":"gate6","temperature":28.1,"humidity":66}

Required header in a backend-enabled implementation: x-litme-token: YOUR_DEVICE_TOKEN. Keep the token private.

Sensor confirmation behavior

  • Green / passable: controller has confirmed the path clear using its approved logic.
  • Red / obstructed: controller confirmation logic detects a blockage and activates the local buzzer.
  • Unknown / offline: no fresh trustworthy report is available, or the sensor/controller is disconnected.
  • Temperature: only show measured sensor readings. Missing readings remain unavailable.

Use freshness timeouts on the controller or gateway. Never turn a stale reading into a green status.
